✅ **Wave 1 — Open Redirect Fix**
- Added `isSafeRedirect()` function to login.html (lines 359-368)
- Validates `?redirect=` parameter before passing to `window.location.href`
- Only allows relative paths (`/...`) and same-origin absolute URLs
- Blocks `//` protocol-relative and external URLs
- Severity: 🔴 CRITICAL → ✅ Fixed

✅ **Wave 1 — Firestore Rules Ownership Scoping**
- Applied `hasProfileAccess(profileId)` to 4 collections: payoutRequests, userNotifications, userState, taskProposals
- All read/write/delete ops now verify user owns or administers the profile
- Uses existing isProfileOwner() + isProfileAdmin() helpers
- Known limitation: Requires Firestore profile doc to exist (localStorage-only profiles fail checks)
- Severity: 🔴 CRITICAL → ✅ Fixed

✅ **Wave 2 — Removed localStorage Admin Fallback**
- admin.html no longer falls back to localStorage when Firestore is unavailable
- Firestore is now the sole authority for admin status
- Trade-off: Admins cannot use dashboard offline (acceptable — admin ops require Firestore anyway)

✅ **Wave 2 — PROFILE_ID Validation**
- Added regex validation: `/^[a-zA-Z0-9_-]+$/`
- Applied to app.html and admin.html before using PROFILE_ID in localStorage keys or Firestore paths
- Prevents crafted values from reading/writing arbitrary keys or targeting unintended Firestore paths

✅ **Wave 2 — Sign-Out Cleanup**
- login.html signOut() now clears all `hr_*` localStorage keys:
  - hr_profile_*, hr_state*, hr_admin*, hr_pending_*, hr_user_profiles_*, hr_additional_admins*
- Prevents data inheritance on shared devices (kid's tablet, school computer)
- Collection strategy: Gather keys into array first, then clear (avoids iteration issues)
