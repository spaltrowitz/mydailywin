## Task

## Critical Issues (Fix First)
1. **Firestore rules auth-only, not user-scoped** (firestore.rules) — ANY authenticated user can read/write ANY other user's data. Requires document ownership scoping.
2. **taskProposals allows unauthenticated creates** (firestore.rules:90) — `allow create: if true` opens abuse vector. Change to `if request.auth != null`.
3. **No data validation in Firestore rules** — no request.resource.data validation. Any authenticated user can write arbitrary fields/types.
4. **Debug logging leaks API keys** (admin.html:1874-1889) — console.log outputs EMAILJS_PUBLIC_KEY and service/template IDs in production.

## High Priority Improvements
5. **Dead Cloud Function** (functions/index.js) — sendAdminInvite uses SendGrid but never called. Admin.html uses EmailJS instead. Decision needed: use Cloud Function (secure) or EmailJS (simple). Recommendation: migrate to Cloud Function.
6. **No caching headers** (firebase.json) — no Cache-Control for static assets. Browsers re-fetch everything. Needs headers section with max-age for CSS/JS/SVG.
7. **innerHTML XSS risk** (45+ instances) — profile/task/reward names from localStorage injected without sanitization.
8. **Service Worker never versions cache** (sw.js:6) — CACHE_NAME always 'habitrewards-v1'. Users get stale cached pages indefinitely.

## Medium Priority Decisions
9. **localStorage not a database** — 20+ keys per profile. Breaks on new device, cleared storage, private browsing, >5MB limit. Decision: migrate to Firestore-first with localStorage as offline cache only.
10. **Dual email system confusion** — EmailJS (client) and SendGrid Cloud Function (server) both exist for same purpose. Only EmailJS wired. Decision: pick one, delete other.
11. **Auth token not verified in Cloud Function** (functions/index.js:32) — cors: true, no ID token verification. Anyone can POST to it.
12. **Login flow missing edge cases** — no password reset, email verification, Google popup fallback, race condition in sessionStorage.
